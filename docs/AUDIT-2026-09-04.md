# Reliability audit — September 4, 2026

Scope: a targeted code and regression audit of conversation continuity,
gateway sign-in, MCP settings, and Bot/group execution. This is not a full
security assessment or an accessibility certification.

## Confirmed issues and corrections

| Priority | Issue | Correction | Regression coverage |
| --- | --- | --- | --- |
| P1 | Late history/send/retry results could replace the newly selected conversation. | Responses must still belong to the current selection and gateway. | `conversation-races.test.tsx` |
| P1 | Failed sends could overwrite newer draft edits; delayed file reads could attach to another Bot. | Preserve the original draft and newer text; discard attachment reads after navigation. | `conversation-races.test.tsx` |
| P1 | Canceling OAuth did not invalidate every pending response. | Check attempt ownership before redirecting or accepting completion, including rejected old attempts. | `gateway-ui.test.tsx` |
| P1 | A rejected prompt could remain marked running indefinitely. | Release running state and publish a structured failure to subscribers. | `backend-reliability.test.ts` |
| P1 | Concurrent requests could resume the same thread twice and submit overlapping prompts. | Share in-flight session hydration and reject overlapping submissions. | `backend-reliability.test.ts` |
| P1 | A stopped group could advance while session creation or interruption was pending. | Invalidate the run before interruption and recheck ownership after asynchronous work. | `backend-reliability.test.ts` |
| P2 | A late MCP save could render another Bot's configuration. | Scope tests, saves, feedback, and busy state to the selected configuration request. | `settings-races.test.tsx` |

Successful gateway mutations must refresh the application even if the settings
panel has closed. Only panel-local state updates are suppressed after unmount;
closing settings is not a rollback of a committed Bridge configuration change.

## Verification and limits

- Local validation: 210 unit/integration tests; six browser/Windows Electron
  journeys passed (the macOS-only journey is skipped on Windows); production
  Web/Bridge/Electron build and built Bridge startup passed. The production
  dependency audit reported zero vulnerabilities. These are point-in-time
  results, not a guarantee that every application path is covered.
- Unit/integration regressions exercise delayed, canceled, rejected, and
  concurrent requests with deterministic fixtures.
- Existing browser journeys cover first launch, thread restoration, retry,
  profile transfer, mobile layout, keyboard navigation, and large histories.
- The Windows Electron smoke journey exercises custom window controls and
  external OAuth navigation. The macOS-specific journey requires a macOS runner.
- Production dependency audit, production build, bundle budgets, and built
  Bridge startup are release gates. GitHub CI repeats tests on Windows/Linux
  with Node 22/24 and browser smoke journeys on Linux/macOS.
- Mock-based tests do not prove compatibility with every deployed Hermes
  configuration or identity provider. No production Hermes configuration or
  credentials were changed for this audit.
- No new installer or signing/notarization qualification is included in this
  source-code publication. Downloadable alpha artifacts retain their own version.

## Follow-up

JavaScript and CSS bundles are close to their existing size limits. Keep those
limits enforced; reduce shared code and load optional panels on demand before
adding substantial UI features. Native multi-gateway support and the GitHub
updater remain separate roadmap work, not part of these fixes.
